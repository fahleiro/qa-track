# QA Track v0.2.1

> Patch release — PostgreSQL exposto no host + docker-compose com persistência.

---

## Novidades

### 1. PostgreSQL acessível de fora do container

A porta `5432` agora é exposta (`EXPOSE 3000 5173 5432` no [`Dockerfile`](../../app/Dockerfile)) e
publicada no host, permitindo conexão direta de clientes como DBeaver/pgAdmin.

O Postgres interno já estava configurado para aceitar conexões livres
(`listen_addresses='*'` + `pg_hba` em modo `trust`, ver
[`01_postgres_config.sh`](../../app/sh_scripts/01_postgres_config.sh)) — o que faltava era
publicar a porta no host.

Dados de conexão:

| Campo | Valor |
|-------|-------|
| Host | `localhost` |
| Port | `5432` |
| Database | `qa_test_track` |
| User | `postgres` |
| Password | *(vazio — trust)* |

> ⚠️ Modo `trust` (sem senha) é adequado apenas para dev local. Não exponha a 5432
> assim em produção — use `scram-sha-256` + senha e restrinja o `pg_hba`.

### 2. docker-compose.yml

Novo [`app/docker-compose.yml`](../../app/docker-compose.yml) como forma recomendada de subir
o stack:

```bash
cd app
docker compose up -d --build
```

- Publica `3000` (API), `5173` (frontend) e `5432` (Postgres).
- `restart: unless-stopped` — sobe junto com o Docker.
- **Volume nomeado `qa_pgdata`** em `/var/lib/postgresql/data`: os dados (usuários,
  config de QA, registro do device farm e auditoria) deixam de ser perdidos ao recriar
  o container.

## Compatibilidade

Sem quebras. O único schema é o banco único `qa_test_track` (schemas `public` / `auth` /
`device_farm`), inalterado desde v0.2.0.

Quem já roda via `docker run` manual deve adicionar `-p 5432:5432` para publicar o banco.
