# QA Track v0.2.0

> Minor release — autenticação JWT + Device Farm.

---

## Novidades

### 1. Autenticação por JWT

Endpoints da API agora exigem `Authorization: Bearer <jwt>` (com whitelist explícita para `POST /api/auth/login`, `POST /api/nodes/register|heartbeat` e `GET /api/health`).

- Login default: **admin / admin** (criado no boot se `auth.t_user` estiver vazia).
- Override via env: `ADMIN_USERNAME` / `ADMIN_PASSWORD`.
- Em produção, defina também `JWT_SECRET` e `DEVICE_TOKEN_SECRET`.

**Frontend**: nova tela `/login`, token persistido em `localStorage` (chave `qa_track_jwt`), interceptor 401 redireciona automaticamente.

### 2. Device Farm

Nova feature para listar e reservar devices Android físicos plugados em máquinas remotas (hub-and-spoke).

- **Dashboard**: agrega devices de N node-agents online via fan-out HTTP (cache 3s, polling 5s na UI).
- **Lock transacional**: `FOR UPDATE` no Postgres impede 2 reservas simultâneas; TTL 5 min com keepalive 30s; admin pode forçar liberação alheia.
- **Screenshot**: proxy autenticado para o agent (`adb exec-out screencap -p`).
- **Audit log**: cada liberação (manual / TTL / admin force) vai para `device_farm.t_farm_session`.

Rotas novas: `/api/nodes/*`, `/api/devicefarm/*`.
Páginas novas: `/device-farm`, `/device-farm/:udid`.

### 3. node-agent (programa separado)

Novo subdiretório `node-agent/` na raiz. Programa Express leve que roda na máquina com USB, executa ADB localmente, e se anuncia ao dashboard via REST.

- `GET /agent/health|devices|devices/:udid/screenshot|devices/:udid/info`
- Auto-registro no boot + heartbeat 30s (backoff exponencial se dashboard indisponível).
- Dockerfile com `android-tools-adb` (Linux + USB privileged). No Windows/Mac roda no host.

Ver [`node-agent/README.md`](../../node-agent/README.md).

## Schema

3 schemas no mesmo banco `qa_test_track`:
- `public`      — tabelas qa-track existentes (sem mudança)
- `auth`        — `t_user`, `t_session` (novas)
- `device_farm` — `t_node`, `t_device`, `t_device_lock`, `t_farm_session`, `t_apk` (novas)

SQLs aplicados em ordem no boot: `01_create_tables.sql` → `02_auth.sql` → `03_device_farm.sql`.

---

## Compatibilidade

**Quebra**: chamadas externas à API agora exigem JWT. Quem consumir `/api/system`, `/api/scenario`, etc. via curl/script precisa primeiro fazer `POST /api/auth/login` e incluir o token nas chamadas seguintes.

Schema qa-track existente permanece em `public` — dados antigos não são afetados.

---

## Stack

Mesma de v0.1.x + 3 deps no backend:
- `jsonwebtoken@^9.0.2`
- `bcrypt@^5.1.1`
- `axios@^1.9.0` (usado para fan-out de fan-out HTTP no dashboard)

node-agent (programa separado) usa `express`, `axios`, `dotenv`.
